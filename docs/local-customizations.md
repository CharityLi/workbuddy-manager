# 本地定制清单（升级核对表）

本文件是**人工维护**的清单，用途只有一个：升级到上游最新发布版之后，逐条确认
下面这些「本地有、上游发布版未必有」的功能还在。

「更新日志」页的「生成升级简报」按钮会把这里的二级标题原样列进简报，所以：

- 标题写**用户/维护者能看懂的功能名**，不要写文件名或函数名；
- 每条下面写清**升级后怎么验证**（点哪里、看什么、跑什么命令），验证方式要能
  在一两分钟内做完；
- 功能下线或合并进上游之后**删掉对应条目**，别让清单变成考古现场。

判据：升级完照着这份清单走一遍，没有任何一条需要「想想它以前是什么样」。

---

## 多上游分组（账号池分组）

一个分组 = 一个上游实例 + 一个账号目录 + 一个 API 地址。分组之间账号、密钥、
请求日志互不串。

**升级后验证**：设置 → 上游，能看到分组列表且每组标着服务状态；切到「账号」页，
顶部分组选择器能切换且列表跟着变。

## 分组实例一键起停与开机自启

上游面板为每个分组生成 `instance-<slug>/` 并写 launchd plist，点「启动服务」即
可拉起并登记开机自启；端口被非托管旧进程占用时给出可读提示而不是静默失败。

**升级后验证**：设置 → 上游任一非默认分组点「启动服务」→ 按钮变成「运行中（pid）」，
`launchctl list | grep com.wb2api.gateway` 能看到对应 label。

## 账号回填按分组读日志

聊天行落在网关 stdout、任务行落在 stderr，且每个分组各有一份；回填时按请求所属
分组读对应实例的日志，不会把别的分组的账号算进来。

**升级后验证**：日志页任选一条聊天记录，能看到「账号」列并显示 `昵称(uid前8位)`；
不同分组的记录显示的是各分组自己的账号。

## 「今日消耗积分」统计

按上游 `usage.json` 的 `credit` 累加每个账号当日消耗，账号页有「今日消耗」列，
仪表盘按分组汇总。

**升级后验证**：账号页出现「今日消耗」列且数字随请求增长；仪表盘分组卡片点开后
有当日消耗合计。

## 任务记录解析（猫猫旅行 / 活跃上报 / 自动签到 / 保活 / 夜猫）

从网关日志解析任务行，兼容原生 Go 时间戳前缀；夜猫日志的 `blackcat` 映射成界面上的
「夜猫任务」；日志文件读错时采集器会自检并报出可疑文件，而不是静默空白。

**升级后验证**：任务记录页的类别筛选里能看到上述几类，且列表有当天记录（不是全空）。

## 底部 Dock 栏

移动端与桌面端共用一套 Dock 实现；选中块、标签字号、更多面板高亮、禁用账号角标
都在这里。

**升级后验证**：桌面宽度下底部 Dock 正常悬浮、可拖动；手机宽度下 6 个入口不截断，
「更多」面板里当前页高亮。

## 移动端自动选路 `/route`

书签进 `/route` 时探测局域网 / Tailscale 哪个快；**已登录则留在当前地址**，避免换
地址导致登录态丢失。

**升级后验证**：手机上已登录状态下访问 `/route`，最终停留在原地址且不掉登录；
清掉 cookie 后访问 `/route`，会切到更快的入口并落到登录页。

## 密钥页 Token 单位

已用 Token / 配额按语区显示「万 / 亿」（英文 K/M/B），悬停给出精确数字。

**升级后验证**：密钥页数字显示为 `3619万` / `6.4亿` 这类带单位形式，悬停有千分位原值。

## 更新日志双栏 + 每日上游巡检

「更新日志」页分「本地 / 上游」两栏，上游栏列出 GitHub Releases 正文；后端每天
（默认 10:00，`WB_UPSTREAM_WATCH_HOUR` 可改）查一次有没有新版本，只记录不跟随。

**升级后验证**：设置 → 更新日志默认落在「上游更新」、最新版展开；`GET /api/system/upstream-log`
返回 `latest` 与 `local_version`。

## 升级对比简报

基于本地 tag 集合与 Releases 对比，列出「上游有本地没有的版本」「本地独有提交」
「本清单」，供升级前决策。

**升级后验证**：设置 → 更新日志 → 上游栏点「生成升级简报」，弹窗里有待升级版本列表
和本文件的条目。

## 弹窗点按不留灰框

全局关掉移动端 tap 高亮，并让焦点环只在键盘操作时出现；弹窗内容容器不再画一圈
默认 outline。

**升级后验证**：手机浏览器点开任一弹窗再点按钮，弹窗边缘不出现灰框/描边；桌面键盘
Tab 仍能看到焦点环。

## 重启安全脚本

`scripts/restart-safe.sh` 用 `kill -TERM` + launchd 拉起的方式重启各端，并在启动后
检查重复进程与端口绑定错误。

**升级后验证**：`bash scripts/restart-safe.sh check` 输出「全部正常」，退出码 0。
